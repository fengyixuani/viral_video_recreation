# 商品参考图规划 Skill

## Skill 名称

商品参考图规划（Product Reference Image Planner）

## Skill 定位

拿到用户素材、写出爆款复刻的新剧本后，为**每一个商品**准备 1–5 张最有价值的商品参考图。
这些参考图将用于后续的商品识别、视觉理解、图片生成、视频生成与广告创意。

核心目标：

> **用尽可能少的图片，让视觉模型完整、准确地理解商品的真实外观、结构、状态和关键特征。**

本 Skill 负责三件事：

1. **规划**：先不看素材，决定这个商品需要哪几张参考图（需求清单）
2. **匹配**：拿需求清单到已有素材里找候选：用户商品图 → 图片素材 → 视频素材抽帧
3. **处置**：为每条需求给出唯一结论——直接使用 / 改造后使用 / 缺失

流水线落地顺序（`pipeline.step_product` + `step_generate`）：

```text
_index_product_images  每张商家图一次结构化理解（caption / 展示信息 / 视角 / 完整性 /
                       是否局部 / 商品占比 / 干扰），产物 product/image_index.json
_select_refs           只读这份结构化理解挑基准参考图并排序，@图片1 必须是完整全貌
_refine_user_images     只对选中的图判断要不要编辑；结构化理解里无干扰的直接用
_plan_shot_refs        剧本出来后按镜分配参考图（generated/shot_refs.json）：
                       每一镜只带它画面里真正要出现的角度/配色，不出商品的镜不带图，
                       剧本要而素材没有的角度记「缺失」；同时判这一镜要不要中间状态图。
                       选中了前面没体检过的图（换装素材几十张，只有前几张进全局参考图）
                       就当场补一次编辑判断/改造——没体检的实拍图常带真人脸，
                       直接下发会被视频模型风控拒掉，整段掉到文生视频、商品信息全丢
_make_state_images     中间状态图：视频模型一次画不准的关键状态（开合/界面显示/指示灯/
                       贴合形态/多机摆位）先用图像编辑锁成一张图，排在参考图最前面，
                       视频模型只负责状态之间的动态变化。先在已有图里匹配，没有才生成；
                       生成一张一张跑，验收多一条「状态达成」，做不出来就放弃这张
```

前三步回答「这个商品长什么样」（与剧本无关，必须先有，写剧本要用），第四步回答
「这一镜需要哪张」——卡点换装、多配色对比这类剧本每拍要的图不一样，全片共用一组图会被
模型混搭成四不像。

先理解、再选图、最后才判断编辑——顺序不能颠倒：不知道每张图展示了什么信息，就只能按
文件顺序凑参考图，@图片1 很容易是个局部特写，生成端照着它编出假商品。

实际的图片改造（白底化、去文字、放大主体）不在本 Skill 内执行，
指令格式见 **ProductImageEditSkill**，由 `_refine_user_images` 落地：
VLM 看图**一次写好**一条编辑指令（点名画面上具体的文字、贴片、水印），
再按这条指令一张一张生成，每出一张就与原图比对，不过关就把走样点写进指令再出一张（最多 3 张）。

# 一、核心原则

## 1. 完整商品优先

这是最高优先级原则。

**优先选择能够看到商品完整全貌的图片。**

理想图片应该：

* 商品主体完整出现在画面中
* 商品没有被裁切
* 商品的主要轮廓清晰可见
* 商品的重要结构没有被遮挡
* 能够判断商品整体尺寸、比例和形态
* 能够识别品牌、包装和产品设计

不要因为局部细节更清晰，就牺牲商品整体结构。

### 优先级

```text
完整商品图
    >
完整商品 + 关键细节可见
    >
局部但具有关键结构信息
    >
纯局部特写
```

## 2. 忠于素材

参考图的唯一使命是**还原真实商品**。素材里没有的视角、状态、结构，
宁可标记「缺失」，也绝不允许用生成能力凭空补一张——
假参考图会被下游生视频原样照抄，比没有参考图更糟。

---

# 二、局部图必须严格控制

**默认尽可能不选择局部特写。**

只有当某个关键视觉信息无法通过完整商品图可靠表达时，才允许增加局部图。

例如：

* 手机摄像头模组
* 手表表盘
* 鞋面特殊纹理
* 包包特殊五金
* 化妆品瓶口结构
* 食品颗粒 / 粉末的真实状态

即使需要局部图，也必须先确认：

> 这个细节是否真的会影响后续模型对商品的理解或生成？

如果不会，则不要选择。

---

# 三、参考图数量

最多选择 **5 张**。

推荐数量：

```text
1 张：商品简单，单张完整图已经足够
2 张：需要两个互补视角 / 状态
3 张：商品具有多个重要视觉维度
4 张：商品结构较复杂
5 张：只有复杂商品才允许达到上限
```

**绝不能为了达到 5 张而增加重复图片。**

如果 2 张已经足够，就只选择 2 张。

---

# 四、阶段一：建立参考图需求清单

参考图需求不是固定的「正面、侧面、背面」。
**先不看素材**，从商品结构与剧本（商品会怎么出镜）出发，回答以下五个问题：

### 1. 商品身份

哪张图能准确说明「这到底是什么商品」？
关注：整体轮廓、品牌、Logo、产品名称、包装、独特设计。

### 2. 商品整体形态

是否能理解：长宽高比例、整体轮廓、材质、颜色、结构、主要部件关系。

### 3. 关键视角

哪些视角能补充完整商品图无法表达的信息（正面 / 背面 / 侧面 / 45° / 顶部 / 底部）。
不要机械要求每个商品都拥有这些视角。

### 4. 商品状态

是否存在重要状态变化：完整 / 打开 / 展开 / 拆封 / 折叠 / 组合 / 分离 / 使用中。

**状态变化有时比拍摄角度更加重要。**

### 5. 内部结构 / 内容物

内部结构或内容物有重要视觉价值时才考虑。例如燕麦：

```text
完整包装 → 打开包装 → 内部袋装 → 燕麦内容物
```

而不是机械的「正面 → 侧面 → 背面」。

每条需求写成三元组：**image_role（承担什么任务）+ view_or_state（视角或状态）+ why_needed**。
需求清单是理想情况，后面允许被素材现实打折：素材里没有的需求走「缺失」，不虚构。

---

# 五、阶段二：收集候选图

## 来源优先级

```text
用户上传的商品图
    >
已有图片素材（营销图、详情页、截图等）
    >
视频素材抽帧
```

前一级能满足的需求不要往后找；后一级只补前一级的缺口。

## 图片素材匹配

把每条需求与所有已有图片逐一对照。注意：用户上传的商品图**同样要过阶段三的检查**，
营销图上常有大字报、促销贴片，或商品只占画面一角，不能因为是用户传的就直接采信。

## 视频素材抽帧（图片里找不到时）

* 从素材切片索引里挑**商品露出最完整、最清晰**的片段：优先特写 / 近景、商品居中、
  没有手部或其它物体大面积遮挡的片段
* 在片段内选商品最清楚、画面相对静止的时间点抽帧，避免运动模糊
* 同一需求可抽 1–3 个候选帧，进入阶段三择优
* 抽出来的帧和普通图片同等对待：不达标同样走「改造后使用」

## 全都没有

该需求标记「缺失」并写明原因。**绝不允许**用文生图凭空编一张商品图来填坑。

---

# 六、阶段三：完整性与质量检查

每张候选图必须过三道检查。

### 检查 1：商品是否完整？

* 是否被裁切 / 缺少顶部 / 缺少底部 / 缺少重要部件
* 是否有物体遮挡 / 超出画面 / 只有局部

商品主体不完整，降低优先级。

### 检查 2：商品是否清晰？

* 是否严重模糊 / 过曝 / 欠曝 / 严重反光 / 运动模糊 / 被遮挡

### 检查 3：能否直接当参考图？（决定要不要改造）

逐项判断：

* **文字与贴片**：营销大字、促销角标、价格标签、水印是否覆盖或紧贴商品主体
  （商品包装自身印刷的文字不算干扰，是商品身份的一部分）
* **商品占比**：商品主体占画面明显偏小（低于约 1/3 就算小）
* **人与手**：是否有手持、模特出镜（下游视频生成对真人人脸有风控，含人图不能直接下发）
* **背景**：纯色 / 干净 > 简单生活场景 > 杂乱堆叠
* **构图**：商品是否居中、是否和其它商品挤在一起

三档结论：

```text
干净可直接用
主体清楚但有干扰      → 可改造
主体不可辨认          → 不可用（换候选或标记缺失）
```

判「可改造」时，**直接写出一条编辑指令**（不要只给笼统的「去掉营销文字」）：
画面上叠加的文字把原文抄出来，贴片、水印、logo 逐个点名位置，格式见「改造要求怎么写」。
注意区分：商品包装自身印刷的品牌名 / 产品名是商品身份的一部分，必须显式要求保留。

---

# 七、图片选择评分

对同一需求的多张候选图综合评分：

```text
完整性       30%
商品识别度   20%
整体结构     20%
视觉清晰度   10%
独特信息     10%
状态信息      5%
细节信息      5%
```

但是：

> **局部图不能因为细节分数高，就超过一张高质量完整商品图。**

完整性属于硬约束，而不是普通加权项。
「能否直接当参考图」的问题（文字多、占比小等）不参与打分，在阶段四用「改造」解决——
一张完整但带促销文字的图，仍然优于一张干净的局部特写。

---

# 八、阶段四：处置决策

对每条需求的最佳候选，给出唯一处置：

```text
直接使用     完整、清晰、干净                    → 直接进 Reference Set
改造后使用   主体可辨认，但有文字/占比小/背景乱/有手 → 写清编辑指令，交给图生图改造
缺失         所有候选都不可用，或素材里根本没有      → 记入「缺失」清单并说明原因
```

## 改造要求怎么写

一条指令写完，商品用「」括起来的通用名指代，格式：

```text
「手机」保持不变，删除顶部「xiaomi 17 Pro Max」大字、删除右上角「小米徕卡联合研发」红标、删除右下角水印。删除人物。修改为白底图，「手机」占据主要画面。删除右边多余的「手机」，删除手。生成商品主图，「手机」居于正中，放大。
```

* 目标视角 / 状态**必须与源图一致**：源图是正面，就只能要「正面白底图」，不能拿正面图要背面
* 要删的元素逐个点名：叠加文字抄原文、贴片 / 水印 / logo 写清在画面哪个位置
* 必须显式要求保留：外形结构、材质质感、配色、**包装自身印刷的文字**
* 画面里没有的不要写（没有手就别写删除手）

## 两条禁令

1. **不造未见结构**：需求清单里要「背面」，但素材里没有任何背面画面 → 处置只能是「缺失」，
   不能让图像编辑去想象一个背面。
2. **不走线稿链路**：商品图改造必须走图生图编辑（原图进 ref_images）。
   人物线稿链路（line_art / describe_person）只提取人物外观信息（发型 / 服装 / 体型），
   商品图过一遍会变成一张人物图，商品信息全部丢失。线稿链路只用于真人人脸的风控规避。

# 九、图片之间的冗余检查

选定后必须二次检查。对每两张图片询问：

> 「第二张图片是否提供了第一张图片已经包含的主要视觉信息？」

如果是，删除信息价值较低的一张。尤其避免：

```text
完整正面
完整正面稍微偏左
完整正面稍微偏右
完整正面不同背景
```

---

# 十、商品类型的动态策略

不要预设固定模板，按商品自身结构动态决定。

## 手机

```text
1. 完整正面
2. 完整背面
3. 完整侧面
4. 必要时摄像头区域
```

一张 45° 完整图能同时表达正面 / 侧面 / 背面大部分信息时，减少数量。
摄像头特写不是默认必须。

## 燕麦 / 食品

```text
1. 完整商品包装
2. 打开后的完整状态
3. 内部包装 / 袋装
4. 内容物完整展示
```

一张完整打开状态同时看到包装和内容物时，优先用这一张。颗粒特写属于补充信息。

## 鞋

```text
1. 完整鞋体 45° / 侧面
2. 完整鞋底
3. 必要时完整另一侧
4. 必要时材质 / Logo
```

## 包

```text
1. 完整包体
2. 完整背面 / 侧面
3. 完整打开状态
4. 必要时内部结构
```

内部结构重要时，优先「完整打开」的照片而不是内袋局部特写。

## 化妆品

```text
1. 完整产品
2. 完整包装 / 盒体
3. 打开状态
4. 必要时内容物
```

# 十一、执行流程

```text
Step 1   识别商品（名称、品类、结构）
Step 2   分析商品视觉结构，结合剧本确认商品出镜方式
Step 3   建立需求清单（1–5 条，image_role + view_or_state + why_needed）
Step 4   收集候选：用户商品图 → 图片素材 → 视频素材抽帧
Step 5   每张候选做 完整性 / 清晰度 / 可用性 三道检查
Step 6   每条需求择优，给出处置：直接使用 / 改造后使用 / 缺失
Step 7   冗余检查，删除重复信息的图
Step 8   最终完整性检查（只看这 1–5 张能否讲清商品）
Step 9   输出 JSON
```

---

# 十二、硬性规则

### Rule 1
**完整商品图优先于局部图。**

### Rule 2
**默认尽可能少使用局部图。**

### Rule 3
**不能为了展示细节而牺牲商品整体形态。**

### Rule 4
**1 张高质量完整图 > 多张低价值局部图。**

### Rule 5
**如果完整图已经表达某个细节，不要再增加该细节的特写。**

### Rule 6
**局部特写必须有明确的信息价值。**

### Rule 7
**最多 5 张，但不要求必须达到 5 张。**

### Rule 8
**不同图片必须尽可能提供互补信息。**

### Rule 9
**商品状态变化可以比传统拍摄角度更重要。**

### Rule 10
**不能凭常识推测素材中不存在的商品结构。**

### Rule 11
**改造只能还原源图中已经看得见的视角与状态。**
屏幕/表盘/界面的显示内容同样受此约束：素材里没有的壁纸角色、界面画面、成段文字，
不许用图像编辑造出来（中性的黑屏/亮屏除外）。

### Rule 12
**商品图改造走图生图编辑链路，禁止走人物线稿（line_art）链路。**

### Rule 13
**需求满足不了就输出「缺失」，不允许文生图凭空造商品图。**

### Rule 14
**图上叠加的营销文案是文字信息，不是画面事实。**
文案宣称的功能画面（壁纸角色、界面动效等）不得写进商品外观、不得成为状态图的目标状态、
不得出现在剧本画面里；它只能作为文字卖点进台词或字幕。
（case 17：img3 营销小字「超拟人熊猫萌宠」被当成屏幕壁纸，剧本与状态图全链造出了素材里
根本不存在的熊猫。）

# 十三、最终输出

输出 json，供流水线直接消费：

```json
{"商品": "",
 "参考图": [
   {"need_id": "R1",
    "priority": 1,
    "image_role": "商品整体",
    "view_or_state": "正面全貌",
    "completeness": "完整",
    "来源": {"type": "用户商品图 | 图片素材 | 视频抽帧",
             "file": "图片路径或抽帧产物路径",
             "源视频": "仅抽帧时填",
             "抽帧秒数": 0.0},
    "质量问题": ["促销文字覆盖", "商品占比小"],
    "处置": "直接使用 | 改造后使用",
    "改造要求": "处置=改造后使用时必填。例：「手机」保持不变，删除顶部「限时直降300」大字、删除右下角水印。修改为白底图，「手机」占据主要画面。生成商品主图，「手机」居于正中，放大；保持正面视角与包装印刷文字不变",
    "why_selected": "",
    "information_covered": ""}],
 "缺失": [
   {"image_role": "背面结构",
    "why_needed": "",
    "结论": "素材中无任何背面画面，按 Rule 13 不虚构"}]}
```

字段约定：

### image_role

商品整体 / 正面结构 / 背面结构 / 侧面结构 / 打开状态 / 展开状态 / 内部结构 / 内容物 / 关键细节

### completeness

只能使用：`完整` / `基本完整` / `局部`。

> **除非局部图片具有不可替代的关键视觉信息，否则优先选择「完整」或「基本完整」的图片。**

---

# 十四、最终判断标准

最终不要问：

> 「这个商品应该有哪些角度？」

而要问：

> **「如果后续视觉模型只能看到这 1–5 张图片（含改造产物），它是否已经能够尽可能准确地理解这个商品的完整外观、结构、状态和关键特征？」**

如果答案是「是」，停止增加图片。

如果答案是「否」，找到**信息缺口最大的维度**，再增加一张最能填补该缺口的图片；
素材里找不到就记入「缺失」。

最终目标：

> **最少图片 + 最大完整性 + 最大视觉信息覆盖 + 最低冗余 + 零虚构。**
